# Упрощённые сценарии: контракт реализации

Фактические маршруты и HTTP-схемы: [OpenAPI JSON](openapi.json), [OpenAPI YAML](openapi.yaml). Тело сценария в FastAPI остаётся обычным `dict`: OpenAPI не объявляет для `graph` отдельную типизированную Pydantic-модель. Правила ниже проверяет `backend/korsik/simple_scenarios.py`.

## Версия и общий запуск

Сценарий хранится в `scenario_version.data.graph`. Новый редактор использует:

```json
{
  "schema_version": "korsik-scenario-v2",
  "algorithm_version": "calendar-v1",
  "editor_mode": "SIMPLE",
  "start_policy": {
    "condition": "ON_BOT_START",
    "timezone": "Europe/Moscow"
  },
  "resume_policy": { "reminder_hours": 24, "max_reminders": 3 },
  "start_step_key": "message_hello",
  "source_mapping": [],
  "steps": [
    {
      "step_key": "message_hello",
      "kind": "MESSAGE",
      "trigger": { "type": "AFTER_PREVIOUS" },
      "content": {
        "text_ty": "Добро пожаловать! Пройти опрос?",
        "text_vy": "Добро пожаловать! Пройти опрос?",
        "custom_prompts": [
          { "id": "lunch", "label": "Где пообедать?", "query_text": "Где находится столовая?" }
        ]
      },
      "transitions": [
        { "target_step_key": "answer_yes" },
        { "target_step_key": "answer_later" }
      ]
    },
    {
      "step_key": "answer_yes",
      "kind": "ANSWER",
      "answer": { "label_ty": "Да", "label_vy": "Да" },
      "transitions": [{ "target_step_key": "survey_welcome" }]
    },
    {
      "step_key": "answer_later",
      "kind": "ANSWER",
      "answer": { "label_ty": "В другой раз", "label_vy": "В другой раз" },
      "transitions": [{ "target_step_key": "finish" }]
    },
    {
      "step_key": "survey_welcome",
      "kind": "SURVEY",
      "survey_template_version_id": "<ID опубликованной версии опроса>",
      "trigger": { "type": "AFTER_PREVIOUS" },
      "transitions": [{ "target_step_key": "finish" }]
    },
    { "step_key": "finish", "kind": "END", "transitions": [] }
  ]
}
```

В примере нужно заменить ID версии опроса реальным значением из `/api/v1/survey-templates`.

| `start_policy.condition` | Когда запускается |
| --- | --- |
| `ON_BOT_START` | После подтверждённого подключения/старта сотрудника в MAX; `started_at` фиксируется один раз. |
| `START_DATE` | Опорная дата — `employee.start_date`, начало суток в выбранном часовом поясе. Отрицательный сдвиг блока позволяет отправку до выхода. |
| `SCHEDULED` | Обязательны `date: "YYYY-MM-DD"` и `time: "HH:mm"`; сценарий не отправляет сообщения раньше этого момента. |

Кабинет записывает `timezone: "Europe/Moscow"`; backend проверяет действительный IANA-пояс. Для `ON_BOT_START` также действует запрет отправки раньше `started_at`. Повторный старт не создаёт второй маршрут для той же пары «сценарий + период найма», не сбрасывает ответы и не перезапускает завершённый маршрут.

## Блоки, кнопки и связи

- `MESSAGE`: `content.text_ty/text_vy`; кабинет SIMPLE редактирует один текст и сохраняет его в оба поля. `asset_ids` — необязательные материалы `SCENARIO_MATERIAL`, доступность проверяется перед отправкой.
- `ANSWER`: `answer.label_ty/label_vy`; одно поле кабинета заполняет обе подписи. Соединённые с сообщением блоки `ANSWER` становятся кнопками под этим сообщением. Сам `ANSWER` отдельного сообщения не отправляет. Продолжение задаётся исходящей стрелкой ответа.
- `SURVEY`: `survey_template_version_id` указывает конкретную опубликованную версию из раздела «Опросы». Сервер сохраняет `survey` со всеми вопросами, заголовок и область доступа. Внутренние ID вопросов получают префикс ID блока: два включения одного шаблона не смешивают ответы. Смена опубликованной версии шаблона не заменяет уже закреплённый опрос.
- `END`: завершает маршрут, не отправляет сообщение, не имеет исходящих связей. Одиночный `END` также завершает маршрут без отправки.

Сообщение соединяется либо с одним следующим блоком, либо с 1–10 ответами. Смешивать автоматическое продолжение с вариантами ответа нельзя. Другие блоки имеют не более одного продолжения. Все блоки должны быть достижимы от начала; циклы, повторяющиеся ID/связи и неизвестные цели запрещены. `ANSWER` присоединяется только к сообщению, сценарий не начинается с ответа. Связи не содержат сложных условий: `condition` отсутствует либо равен `{ "kind": "ALWAYS" }`.

`step_key` генерируется при создании блока и показывается как `ID: …`; редактор не предлагает его менять. Старый флаг `mandatory` в SIMPLE не вводит обязательность. При добровольном отказе от опроса маршрут может продолжиться.

## Расписание блока и повтор

У `MESSAGE` и `SURVEY` два варианта `trigger`:

```json
{ "type": "AFTER_PREVIOUS" }
```

После завершения предыдущего блока; у первого — после общего запуска. `offset_days`, `local_time`, месяцы и номера рабочих дней здесь не передаются. Поля сдвига и времени в кабинете отключены.

```json
{ "type": "ANCHOR_TIME", "offset_days": 2, "local_time": "10:00" }
```

Календарный сдвиг считается **от даты общего запуска сценария**, а не от предыдущего сообщения. Для `START_DATE` это дата выхода. Для `SCHEDULED` — выбранная дата. Последующий блок всё равно ждёт завершения предыдущего; просроченное время не позволяет отправить его до завершения предшественника. Для `SCHEDULED`/`ON_BOT_START` итоговый срок также не раньше общего запуска. `ANSWER` и `END` собственного расписания не имеют.

`resume_policy.reminder_hours` задаёт интервал повтора последнего ожидающего действия. `resume_policy.max_reminders` ограничивает число повторений на каждый незавершённый шаг (0–100, 0 отключает напоминания). Новые графы получают 3; существующие графы без поля сохраняют прежнее отсутствие лимита. Счётчик увеличивается один раз после фактической доставки MAX, сбрасывается при продвижении к следующему шагу; достижение лимита не завершает шаг и не мешает ответить. Неизвестная доставка блокирует следующий повтор. Для сообщения с вариантами ответа повторяется это сообщение с кнопками; для опроса предлагается продолжить с текущего вопроса. Начало сценария и уже завершённые блоки не повторяются. Пауза маршрута, завершение найма, отсутствие подтверждённого MAX и режим передачи диалога человеку приостанавливают автоматические отправки. Очередь и проверка перед доставкой отсекают устаревшее напоминание после продвижения маршрута/завершения опроса.

Продвижение сообщения происходит после подтверждённого принятия MAX, а не после постановки в очередь. Сообщение с `ANSWER` после доставки ждёт выбора; выбор фиксируется в `journey.answers["choice:<ID сообщения>"]`. Повтор той же кнопки идемпотентен, сменить уже выбранную ветку старой кнопкой нельзя. Состояние маршрута хранит `last_step_key`, `waiting_step_key`, `completed_steps` и события завершения. Общая очередь ввода сотрудника не открывает два опроса одновременно.

## Формулировки для поиска

`MESSAGE.content.custom_prompts` — необязательный список `{ id, label, query_text }`. Он может отсутствовать или быть пустым. Кнопка запускает обычный RAG-поиск по закреплённому в сценарии вопросу и **не выбирает ветку ANSWER**.

Базовые формулировки редактируются отдельно: «База знаний → Основные формулировки». `GET/PUT /api/v1/knowledge/basic-formulations` работают в области доступа HR; GET возвращает ETag, PUT требует `If-Match`. Изменения сохраняют отдельные ревизии. Базовые кнопки добавляются на начальное сообщение сценария и в приветствие/меню бота; собственные формулировки сообщения дополняют их.

## Ограничения

| Поле | Ограничение |
| --- | --- |
| Блоки | 1–500, уникальный `step_key` до 120 символов: буквы ASCII, цифры, `_ . : -` |
| Текст сообщения | Непустой; до 3900 символов в каждой форме обращения. Перед отправкой повторно проверяется длина после подстановки переменных. |
| Ответы под сообщением | До 10; подпись до 80 символов |
| Собственные формулировки | До 12; уникальный ID; подпись 1–80, вопрос 1–8000 символов |
| Базовые формулировки | 1–8; подпись 1–60, вопрос 1–2000 символов |
| Сдвиг блока | Целое число от −365 до +365 календарных дней; время `HH:mm` |
| Повтор | Целое число от 1 до 168 часов; по умолчанию 24 |
| Материалы сообщения | До 10 доступных файлов; при утрате доступа отправка приостанавливается для проверки HR |
| Черновик `graph` | До 2 000 000 символов JSON-представления; незавершённый ограниченный черновик можно сохранить, публикация требует успешной проверки |

## Рабочий цикл API и совместимость

1. `POST /api/v1/scenarios` создаёт схему; `/scenarios/{id}/versions` с `{ "editor_mode": "SIMPLE", "base_version_id": "…" }` создаёт черновик. SIMPLE-база копируется; для старой схемы создаётся **отдельный новый пустой маршрут с приветственным блоком**, без преобразования прежних вопросов/связей.
2. `GET /api/v1/scenario-versions/{id}` возвращает граф и ETag. `PUT` сохраняет `{ "graph": … }` с `If-Match`; сохранение очищает прежние результаты проверки/согласования. Материалы загружаются через `/api/v1/assets`, опубликованный опрос выбирается из `/api/v1/survey-templates`.
3. `POST …/{id}/simulations` принимает `employee` и `answers`, например `{ "choice:message_hello": "answer_yes" }`. Симуляция не отправляет сообщения и показывает выбранную ветку/ожидание ответа.
4. `POST …/{id}/validate` → свежий `GET` для ETag → `POST …/{id}/review` с `action: "APPROVE"` → `POST …/{id}/publish` с `migration_policy: "NEW_ENROLLMENTS_ONLY"` и причиной. Команды сохраняют действующие правила авторизации, CSRF, идемпотентности и ETag.
5. Сотрудник запускает бота с подтверждённой привязкой либо HR явно назначает опубликованную программу. Новая публикация сама не отправляет новую схему существующим сотрудникам; текущий маршрут сохраняет версию.

Старые опубликованные графы и назначения продолжают работать на прежнем движке. Непубликованные старые черновики редактируются в исходном формате; их данные не упрощаются при открытии. «Новый черновик» копирует выбранную версию в её формате. Новые сценарии начинают с SIMPLE. Опубликованные и архивные версии неизменяемы. Управление названиями и мягким удалением описано в [RELEASE23](RELEASE23.md).
