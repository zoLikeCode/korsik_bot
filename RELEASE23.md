# Обновление 23: управление сценариями и повторениями

Раздел и заголовок страницы называются «Конструктор сценариев», создание — «Новый сценарий». На карточке только два статуса: «Опубликован», если у сценария есть опубликованная версия/история публикации, и «Не опубликован» в остальных случаях. Новый черновик не сбрасывает статус карточки. Названия версий в списке продолжают различать черновик, опубликованную и архивную версии.

## Работа в кабинете

- Три точки на карточке → «Переименовать» или «Удалить». Перед удалением показывается подтверждение с названием сценария.
- «Настройки сценария» → название выбранной версии, «Сохранить название», «Удалить черновик». Удаление последнего черновика возвращает пустой список версий; можно создать новый.
- Непубликованные DRAFT/IN_REVIEW/APPROVED редактируются. Изменение APPROVED сбрасывает согласование и возвращает DRAFT. Опубликованные и архивные версии остаются неизменяемыми. У опубликованной версии поля отключены, удаления нет, симуляция доступна.
- Старые черновики calendar-v1 редактируются в своём исходном формате: сообщения, вопросы, встроенные опросы, задачи, сигналы, условия переходов и календарные привязки. Исходные поля и соответствие Excel не преобразуются при открытии. «Новый черновик» копирует выбранную версию в её формате; первая версия нового сценария использует SIMPLE.
- Для SIMPLE с запуском «При запуске» или «Дата выхода» добавлено «Количество повторений» (0–100). Это число напоминаний о последнем незавершённом шаге с указанным интервалом. 0 отключает напоминания. Новые графы получают 3, опубликованные графы без этого поля сохраняют прежний режим. После ответа счётчик нового шага начинается заново.

Веб-интерфейс не отправляет события MAX при редактировании, переименовании или удалении. Публикация сохраняет существующий отдельный путь проверки/согласования.

## Сохранность и API

Удаление родительского сценария меняет статус на ARCHIVED и скрывает карточку из обычного списка. Уже закреплённые версии, ответы, история и запланированные отправки действующих сотрудников сохраняются. Новые назначения архивированного сценария блокируются. После восстановления пропущенные календарные старты автоматически не рассылаются задним числом.

Удалять версию разрешено только в DRAFT и без ссылок из назначенных маршрутов/действий/опросов. Она получает DELETED, содержимое сохраняется. Восстановление требует действующего родителя. Все изменения требуют scope HR и актуального `If-Match`, сохраняются в audit. Физического удаления строк нет.

| Метод | Путь после `/api/v1` | Назначение |
|---|---|---|
| PATCH | `/scenarios/{id}` | `{ "name": "Новое название" }` |
| DELETE | `/scenarios/{id}` | Удаление карточки с сохранением назначений |
| POST | `/scenarios/{id}/restore` | Восстановить сценарий |
| PATCH | `/scenario-versions/{id}` | Переименовать непубликованную версию |
| DELETE | `/scenario-versions/{id}` | Удалить неиспользуемый DRAFT |
| POST | `/scenario-versions/{id}/restore` | Восстановить удалённый черновик |

Для служебного восстановления списки поддерживают `GET /scenarios?include_archived=true` и `GET /scenarios/{id}/versions?include_deleted=true`. Кабинет показывает рабочие списки; восстановление доступно через авторизованный API.

Лимит хранится в `graph.resume_policy.max_reminders`. `reminder_count` относится к ожидающему шагу и увеличивается после фактического подтверждения доставки MAX, не после постановки в очередь. `reminder_sequence` монотонна для уникальных ключей отправки. Повторное подтверждение учитывается один раз под блокировками контекста и маршрута; старое подтверждение не расходует лимит следующего шага. Неизвестная доставка блокирует новую отправку; терминальная ошибка ставит маршрут на паузу для разбора. Достижение лимита не завершает шаг и не мешает сотруднику ответить.
